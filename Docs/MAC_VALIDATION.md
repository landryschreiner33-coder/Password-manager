# Required Mac validation before using real credentials

Requires macOS 14+, Xcode 16+, a signing team, and Touch ID hardware for biometric tests. These checks have NOT been run in the Linux authoring environment.

1. Open `Stillwater.xcodeproj`. Select the Stillwater scheme, My Mac, and your team under Signing & Capabilities. Use a unique bundle ID for distribution and retain it for updates. Build and run. Run `swift test --package-path Core` and the scheme's tests with Command-U. Verify test counts, not just exit codes. The core package has 13 tests; the app suite has 3 tests. CI is provided but has not run here.
2. Create a fictional vault using a long unique master phrase. Close and reopen, verify wrong passwords fail, then unlock correctly. Exercise create, edit, delete, favorites, folder assignment and removal, empty results and search. Quit and reopen after each mutation. Verify the default dark appearance and Settings → Appearance choices (Dark, Light, System), preference persistence after relaunch, switching while settings and sheets are open, and system-theme changes in System mode. Check Increase Contrast, Reduce Transparency, narrow window sizing, keyboard focus, VoiceOver labels, Command-N, Command-F, Command-E, Shift-Command-L, Return and Escape.
3. Enable Touch ID with the current master password. Lock and unlock with Touch ID. Cancel the prompt and verify the vault remains locked; use the master password fallback. Remove/re-enroll fingerprints and confirm the existing item no longer unlocks. Check Keychain access control in a signed sandboxed build: data-protection Keychain, device-only accessibility, biometryCurrentSet. Test with no enrolled fingers and no Touch ID hardware. A mocked cancellation test does not validate hardware access controls.
4. Set inactivity to one minute. Verify active input extends it, background time counts, and timeout removes details, reveal state, editor data, import preview, and settings password inputs. Check sleep, lid close, manual screen lock, Fast User Switching, and wake. These OS events require physical verification; `com.apple.screenIsLocked` is a distributed notification, not a contractual public security boundary. Session-resign and sleep notifications are also monitored. If any screen-lock path fails, block release and replace it with a verified supported mechanism.
5. Copy a fictional password: verify readable, transient/concealed markers and currentHostOnly; verify clearing after 30 seconds and immediately on vault lock. Copy different text before the deadline; it must remain. Confirm Universal Clipboard does not transfer the item to another device. Clipboard managers may ignore concealment markers.
6. Import quoted UTF-8 CSV containing commas, escaped quotes, newlines, empty fields, duplicate records and invalid rows. Confirm required field mapping, masked preview, explicit skip/keep-both, and no silent overwrite. Cancel a preview, then lock. Confirm no temporary plaintext files. Plaintext source CSV remains in its original location; manage it separately, including downloads/trash/backups.
7. Export a backup, move it to another Mac/user with no original Keychain items, restore using its master password, and compare entries and folders. Wrong passwords, truncation and tampering must preserve the current vault. Back up before restoring; restoration replaces rather than merges. Verify recovery from a damaged current envelope using a valid backup.
8. Change master password: old password and old vault key must no longer unlock the current vault; Touch ID is disabled and the app locks. Old backups must still open with their old password. Generate a new backup. There is no reset or recovery method.
9. Run atomic-save failure tests; additionally test disk full, permissions denied, forced process termination during repeated fictional edits, and physical restart after write. File modes must be 0600 and vault directory 0700. Confirm no partial plaintext or partial live vault. Atomic rename protects consistency; power-loss durability still depends on filesystem and hardware.
10. Run Check Unlock Speed on the target Mac and record at least five cold/warm measurements and memory usage. Default is Argon2id v1.3, 64 MiB, three passes, one lane. Do not lower the security floor. Monitor lock responsiveness while deriving keys.
11. Inspect a Release archive with `codesign -d --entitlements :- /path/to/Stillwater.app` and `codesign -dv --verbose=4 /path/to/Stillwater.app`. Verify sandbox, user-selected file access only, hardened runtime, and no release get-task-allow, JIT, unsigned executable memory, network, or library-validation exceptions. Sign with Developer ID, notarize through Xcode Organizer, staple and test Gatekeeper before distribution. A local unsigned build does not establish these protections.
12. Review the app, pinned dependency, key lifecycle, file format, Keychain and memory behavior independently. Verify current Apple API guidance directly (blocked by the authoring environment's network policy). Resolve findings before storing real passwords.
